## 修正刻字机坐标轴方向（回原点时 Y 轴飞转、X 轴反走）

### 部署环境
- 板子：`192.168.11.187`，主机名 `SparKit-015`，RK3399 / Armbian，Node v20.18.1
- SSH：`sparkminds` / `chuangzhi`（本机有 `sshpass`，可直接 scp/ssh）
- 部署目录 `/opt/plotter-one`，属主就是 `sparkminds`（**改文件不需要 sudo**；
  只有 `systemctl restart plotter-one` 需要 `sudo -S`，密码同为 chuangzhi）
- 机器：力宇 SC631-AU，串口 `/dev/ttyACM0` 9600 8N1
- **机械原点在用户正对机器时的右手边**（用户 2026-10-04 上机确认）

### 根因（重要，别再犯）
症状是「点回原点 → Y 轴疯狂转动，X 轴往反方向走」，看着像 X/Y 装反，
实际是代码为了镜像 X 轴发了 **反向 SC**：`SC23622,0,0,27953;`（Xmin > Xmax）。
HP-GL 规范允许这么写，但**力宇固件不支持**——它照样按 `Xmax - Xmin` 算每单位步数，
负分母 → **负缩放系数** → 整机失控。

**教训**：机器出现「疯转」先怀疑自己下发的参数是否合法，别先怀疑轴接反了。

### 修法
- `SC` 恒为正序；方向差异在上位机 `toMachine()`（绝对）/ `toMachineDelta()`（相对）消化。
  这样方向填错最坏只是图形镜像，不会失控撞机。
- 原 selftest 断言的正是这个错误做法（`Xmin>Xmax`），已改为断言 SC 恒正序。

### 同时修掉的其他危险动作（都是同一批指令里的）
- `PR;` + `PA dx,dy;` 在 HP-GL 里是**绝对**移动；相对移动必须写 `PR dx,dy;`
- 收尾 `PA0,0;` 会**真的**把刀头移到 (0,0)；仅切模式要用 `PA;`
- 急停原本发 `PU;PA0,0;`＝急停时还命令机器动一下 → 改只发 `PU;`
- 落刀试压 `lineTo(2,0)` 是绝对移动，落刀状态会划穿材料 → 改相对 2mm
- 进纸 `moveTo(d,0)` 实为横移刀头；该机 **Y 轴就是走纸轴** → 改沿 Y 相对移动
- 手动回原点去掉 `IN;`/`SC;`，只发 `PU;` + `!PG;`（机械归位不掺入坐标假设）
- 校准原先先 `PA` 到材料中心，未归位时是横跨工作台的冲刺 → 改纯相对往返
- `/api/compile` 之前**完全没传** axisX/axisY，界面下拉框对输出毫无作用

### 验证
- 自检 112 项全通过（本机 + 板子各一次）
- 板子上实测下发：回原点 = `PU; !PG;`，方向键右 5mm = `PU; PR-197,0; PA;`
- 已 scp 部署并 `systemctl restart`，网页 HTTP 200、字节数与磁盘一致
- 旧代码备份在 `/tmp/plotter-backup-20261004-211421`

### 待用户上机确认
方向默认值已按「原点在右手边」设为 `axisX=-1`，但**仍需实机跑一次校准向导**确认。
校准是安全的：抬刀、5mm、纯相对往返、没归位也能测。

## 21:20 事故：修完坐标轴后全机按钮失灵（我造成的，已修）

### 现象
用户报「点击什么按钮都不动了」。串口写入成功、任务显示「✔ 完成」，
但机器纹丝不动。**表现和「串口坏了」一模一样**，第一反应会误判成硬件问题。

### 根因：上一版把 `IN;` 删错了
我为了「让回原点只发干净的物理指令」，把 `b.setupCoords()` 整段删掉，
连带删掉了 `IN;`（initialize）。

**力宇固件冷启动后处于未初始化状态，没有 `IN;` 就静默忽略所有运动指令**
——`PU` / `PR` / `PA` / `!PG` 全部无效。所以一个前缀的缺失 = 全机失灵。

### 🔴 教训（比 bug 本身重要）
1. **危险的是反向 SC（负缩放），不是 `IN;`。** 这两件事被我混为一谈了。
   正确做法：`IN;` 保留 + SC 保证正序，两个都成立。
2. **自检断言本身可能是错的。** 我上一版写的
   「手动回原点只发 PU + !PG（不含 IN/SC）」把这个 bug 当成正确行为保护着，
   所以删掉 `IN;` 后自检还能 112 项全绿通过。
   → 断言通过 ≠ 机器能动。**实机行为是唯一裁判。**
3. 这类「静默失败」优先怀疑**下发的指令本身**，其次才是硬件。
   排查顺序：任务日志有没有记录 → 指令内容对不对 → 串口有没有写进去。

### 修复
- `manual.js` / `calibrate.js`：恢复 `IN;` + `SP1;` 前缀；
  归位**仍然不带 SC**（机械归位不掺入坐标假设这点保留）。
- `selftest.js`：把错误的「不含 IN」断言**反过来**写成「必须含 IN」，
  并对 7 类手动指令 + 校准指令逐一断言。
- 自检 120 项（本机 + 板子各一次），已部署重启，`NRestarts=0`。

### 部署注意
- `scp` 偶发 `Connection closed`（一次传 3 个文件时第 3 个失败），
  失败重试一次即可。**每次部署后都要在板子上重跑 selftest 确认**——
  板子上有旧文件残留过一次（selftest 没传上去）。

## 21:30 轴交换：X/Y 物理接反

### 机器的完整轴向事实（截至目前全部实机确认）
| 维度 | 值 | 含义 |
|---|---|---|
| `swapAxes` | `true` | **刀头（龙门）是固件 Y，走纸是固件 X** |
| `axisX` | `+1` | 机器X（走纸）正向 = 材料往里 |
| `axisY` | `-1` | 机器Y（刀头）正向 = 画布 X 增大方向（因原点在右手边） |

推导：交换前机器X=刀头，「原点在右手边」→ axisX=-1。
交换后同一物理事实要落在**机器Y** 上 → 改成 axisY=-1。

### 🔴 我犯的错（值得记）
第一版加 swapAxes 时，**直接沿用了交换前的 `axisX: -1`**。
交换后 X/Y 的物理含义已经变了，那个 -1 落在了错的轴上：
走纸方向反了、刀头方向仍然错。
→ **改 swapAxes 时必须重新推导两个方向的归属，不能沿用旧值。**

### 另一个坑：交换后 SC 幅面上界必须跟着换
交换前机器X走 600mm（幅面宽），交换后走 710mm（走纸方向）。
写死 `preset.width` 会让机器按错误跨度换算坐标、**整体缩放**，
而且不崩不卡、图形照刻，只是尺寸不对——极难察觉。
已抽成 `machineSpanX` / `machineSpanY`。

### 圆弧反射判定
交换（x,y→y,x）也是反射（det = -1），要计入绕向翻转的判定。
偶数次反射 = 旋转，绕向不变。已抽成 `isReflection` getter。

### 校准向导的坑
界面问的是**用户视角**的轴（「刀头往右走了吗」= 画布 X），
但交换后驱动刀头的是**机器 Y**。答「不是」时若按 dir 猜轴会翻错。
写回哪个字段必须跟着 swap 走。

### 状态
- 自检 138 项（本机 + 板子各一次），已部署，`NRestarts=0`
- 界面新增「X/Y 接反了（交换）」下拉，与两个方向下拉正交
- 走纸轴方向（axisX）仍属推断，需用户跑校准第二步确认

## 21:50 修三个问题（狂奔卡死 / 预览崩溃 / 资源实测）

### ① 刀头狂奔卡死（撞机级）
症状：生成指令 → 开始刻绘 → 刀头朝一个方向狂奔到卡死，Y 轴不动。

**根因不是坐标算错**（坐标经核对是对的），而是**任务没有先归位**：
第一条 `PA` 是绝对定位，但机器开刀前停在哪是不确定的。
从「未知位置」跳到「图形起点」距离不可控 → 撞限位。

修：
- `build()` 开头先 `!PG;` 再 `SC` 再绝对定位。顺序即安全性。
- `jobEngine` 收到 `!PG;` 后驻留 3s。串口流式、固件不回执完成。
- 🔴 **没有**发明 `PG1;` 之类固件延时指令——无资料佐证，只能上位机等。
- 🔴 `_sleep` 原来统一 `Math.min(ms,200)`，导致传 3000 也只睡 200ms，
  归位等待形同虚设**且不报错**。已拆成两种语义（capped 参数）。

**教训**：撞机症状要先分清「坐标错」还是「起点未知」——
这次坐标完全正确，方向也被误导了方向。

### ② 预览失败 `i is not defined`
`render.js` 的 `startAnim` 里 `if (i < pts.length) {}`，
`i` 是内层 `for (let i...)` 变量，外层引用 → 越界。那本是死代码，删掉。
另补空子路径守卫（`pts.length < 2` 时 `pts[-1]` 是 undefined → NaN 污染进度）。

**教训**：前端 JS 不在自检范围，`node --check` 只查语法不查作用域。
这类 bug 只能靠实机点按钮发现——所以「实机验证」不能省。

### ③ 顺带修的内存问题
任务历史留 50 条，早期每条带 `text`+`lines` 整份 → 几十 MB 常驻、
跑几天只涨不降。已入历史时剥字段。
⚠️ `list()` 曾读 `j.lines.length`/`j.text.length`，剥字段后**必须同步改**
并给 undefined 兜底，否则界面整个刷不出来。已加测试锁住。

### ④ 资源占用（RK3399 实测，非估算）
- 部署 **400KB**（server 232K + web 152K + data 8K），**零 npm 依赖**
- 内存 **43MB** RSS（主要是 Node 运行时本身）
- 空闲 CPU **<1%**，load 约 0.05；输出中 1-3%
- 温度 **45°C**（被动散热，安全）
- CPU 低的原因是 **9600 波特限速**：76KB 指令光传输就 91s，
  机器走得比数据慢得多。**瓶颈 100% 在机械本身**。
