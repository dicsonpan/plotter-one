# 刻字机 Web 控制服务

**[English](README.md)** | 简体中文

把 Windows 独占的刻字机输出软件（Ucancam / UcanSign、文泰刻绘）搬到浏览器。
一台板子插在刻字机旁边，局域网内任何设备用浏览器打开就能用——Windows、Mac、iPad、安卓手机，
甚至没装任何东西的瘦客户端。

```
                 同一局域网
   ┌────────┐  ┌────────┐  ┌────────┐
   │  电脑  │  │  手机  │  │  平板  │     浏览器，不用装软件
   └────┬───┘  └───┬────┘  └───┬────┘
        └──────────┴───────────┘
                   │ HTTP + WebSocket
                   ▼
        ┌──────────────────────┐
        │  RK3399 / 任意 ARM64 │   常驻 3-5W
        │  Node.js 零依赖      │
        └──────────┬───────────┘
                   │ RS-232 9600 8N1
                   ▼
              力宇刻字机
```

---

## 特点

| | Ucancam / UcanSign / 文泰 | 这个 |
|---|---|---|
| 平台 | 仅 Windows | 任意设备，手机也能用 |
| 安装 | 每台机器装一次 | 浏览器打开就用 |
| 串口驱动 | 需装驱动 | 直接 `/dev/ttyACM0`，无驱动 |
| 离线输出 | 依赖 U 盘 | 直接下发 |
| 依赖 | 商业软件 | **零运行时依赖**（只用 Node 标准库） |

零依赖是刻意的：串口用 `stty` + 文件描述符而不是 `serialport`（后者带 C++ 扩展，
在 ARM64 上要么没预编译、要么要交叉编译）。HTTP 用 `node:http`，
WebSocket 实现了 RFC6455 最小版。**在板子上不需要 `npm install`，部署就是拷贝文件。**

## 部署

把这个服务跑在一台小板子上（RK3399 级别，ARM64），放在刻字机旁边。
它几乎不挑环境：一台装了 Node.js 18+ 的 Linux，加一根 USB 转 RS-232 线就行。
**不需要 `npm install`、不需要构建**——部署就是拷文件。

### 你需要准备

- 一台跑 Linux 的板子（Armbian / Debian / Ubuntu，ARM64 或 x86 都行；RK3399 最合适，常驻 3-5W）。
- 一根 **USB 转 RS-232** 线（±5V 电平）。
  ⚠️ 必须是 RS-232，**不是** USB-TTL（3.3V）。电平不对会烧刻字机控制板。
  常见芯片：CH340、PL2303、FTDI、CP210x。
- 刻字机通电，并用那根线连上板子。
- 同一局域网内任意手机/电脑/平板，用来打开网页界面。

### 第 1 步 — 让板子连上网

把 Armbian（或你用的发行版）刷到板子的 eMMC/SD，启动，用网线或 Wi-Fi 连到网络。
查到它的 IP（看路由器，或在板子上跑 `hostname -I`）。下文把它记作 `<板子IP>`。

### 第 2 步 — 装 Node.js 18+

登录板子（SSH），检查：

```bash
node -v     # 必须打印 v18.x 或更高
```

如果没装或版本太旧，装一下：

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo bash -
sudo apt-get install -y nodejs
node -v     # 现在应该是 v20.x
```

第 4 步的一键安装脚本在缺 Node 时也会自动装，所以这一步可选——但先装好能少踩坑。

### 第 3 步 — 把工程弄到板子上

在板子上：

```bash
git clone https://github.com/dicsonpan/plotter-one.git
cd plotter-one
```

（或者从电脑用 `scp` 拷过去也行——因为没有构建步骤，两种方式都一样。）

### 第 4 步 — 跑安装脚本

```bash
sudo bash deploy/install.sh --port 8080
```

一条命令搞定所有事：

1. 缺 Node.js 18+ 就自动装。
2. 把工程拷到 `/opt/plotter-one`。
3. 建专用系统用户 `plotter` 并加入 `dialout` 组（串口访问权限）。
4. 装 systemd 服务：开机自启、崩溃自动重启。
5. 装 udev 规则，让串口可读写。
6. 放行防火墙端口。
7. 配 mDNS，能用 `hostname.local` 访问，免记 IP。

### 第 5 步 — 浏览器打开控制台

同一局域网内任意设备，打开：

```
http://<板子IP>:8080
```

如果局域网支持 mDNS，`http://armbian.local:8080` 也能用。应该能看到控制台界面。

### 第 6 步 — 连上刻字机

1. 把 USB 转 RS-232 线插到板子和刻字机上。
2. 在界面「设备连接」里选串口设备——通常是 `/dev/ttyUSB0` 或 `/dev/ttyACM0`。
3. 服务启动时会自动连串口，并每 3 秒重试一次，通常不需要手动点「连接设备」。
4. 验证一下是否连通：

   ```bash
   curl -s http://localhost:8080/api/state | grep -o '"connected":[a-z]*'
   # → "connected":true
   ```

#### 怎么找串口

插上线后：

```bash
dmesg | tail -20              # 看内核识别成 ttyUSB0 还是 ttyACM0
ls -l /dev/ttyUSB* /dev/ttyACM*
# 查芯片厂商
udevadm info -a -n /dev/ttyUSB0 | grep -E 'idVendor|idProduct'
```

在界面下拉框里选出现的那个设备即可。

#### 串口参数（力宇机器）

| 参数 | 值 |
|------|-----|
| 波特率 | 115200（默认，支持 9600~230400） |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验 | 无 |
| 流控 | 无（传输不稳可试 RTS/CTS） |

界面默认就是这套参数。

#### 连不上怎么办

```bash
# 1. 权限问题（最常见）
ls -l /dev/ttyUSB0
# 应是 crw-rw---- 1 root dialout ...
sudo usermod -aG dialout plotter
sudo systemctl restart plotter-one

# 2. ModemManager 抢串口（Ubuntu/Debian 常见）
sudo systemctl stop ModemManager
sudo systemctl disable ModemManager

# 3. 被别的程序占用
sudo fuser -v /dev/ttyUSB0

# 4. 手动测串口通不通
sudo apt install minicom
sudo minicom -b 9600 -D /dev/ttyUSB0   # 回车看有没有回显
```

#### RS-232 线缆注意

- **长度**：超过 10-15 米容易掉数据。刻字机离板子远时，加 USB 延长线或 RS-232 中继。
- **交叉还是直通**：RS-232 是交叉（DTE-DCE）。不确定就拔掉 TX/RX 两根对调试一次。
- **接地**：一定要共地，浮地会导致乱码或丢数据。
- **屏蔽**：用带屏蔽层的线，减少电机干扰。

### 第 7 步 — 第一次刻（务必安全）

1. **先空跑**：版面上不放材料，生成一个小方框（比如 50mm）走一遍，看刀路方向对不对。
2. 坐标轴方向和版面朝向已在实机确认并固化进机型预设——日常使用不要去改（改错会让整版镜像或躺倒）。
3. 确认方向没问题，再上料刻。

### 让局域网更好用

**固定 IP** — 编辑 `/etc/network/interfaces`：

```
auto eth0
iface eth0 inet static
    address 192.168.1.100
    netmask 255.255.255.0
    gateway 192.168.1.1
```

**mDNS（免记 IP）** — 安装脚本已配好 avahi，直接访问 `http://armbian.local:8080`。
手机装个 mDNS 浏览器（iOS 用 Bonjour，Android 用类似工具）也能解析。

**添加到主屏幕** — 手机浏览器打开控制台 → 分享 →「添加到主屏幕」。
之后从桌面图标全屏打开，用起来跟 App 一样。

### 日常运维

```bash
systemctl status plotter-one      # 看状态
systemctl restart plotter-one     # 改了配置后重启
journalctl -u plotter-one -f      # 跟日志
```

配置在 `/opt/plotter-one/data/config.json`，改完重启服务生效。

### 升级

```bash
cd plotter-one
git pull
sudo systemctl stop plotter-one
sudo rsync -av --exclude node_modules --exclude data/ ./ /opt/plotter-one/
sudo systemctl start plotter-one
```

### 卸载

```bash
sudo bash deploy/uninstall.sh          # 保留配置
sudo bash deploy/uninstall.sh --purge   # 彻底清除
```

## 支持的机器

力宇 SC 系列（SC631-AU / SC631E / SC801 / SC1261）及其他兼容 HP-GL 的刻字机。

| 机型 | 预设幅面 | 说明 |
|---|---|---|
| **力宇 SC631-AU** | 600 × 710 mm | 保守设定，见下方「⚠️ 幅面」 |
| 力宇 SC631E | 630 × 710 mm | 仅在铭牌确认为 630mm 时使用 |
| 力宇 SC801 / SC801E | 800 × 880 mm | |
| 力宇 SC1261 / SC1261E | 1260 × 1340 mm | |
| 通用 HPGL | 630 × 710 mm | 1016 单位/英寸 |
| 力宇四轴 / 伺服（3D） | 800 × 880 mm | |

**分辨率**：力宇标注 0.0254mm/step 即 1000 步/英寸。
本服务在上位机通过 `toPlotterUnits()` 精确换算为机器脉冲整数步进，直发原生 HP-GL 坐标。
**注意：卷筒刻字机绝不能下发 `SC`（缩放）指令**——卷筒纸 Y 轴为连续进给（无物理上限 $P2_y = 0$），发 `SC` 会导致固件将 Y 轴缩放比例归零，使走纸完全失去响应，且造成 X 轴异常。

### ⚠️ 幅面宽度为什么取 600 而不是 630

SC631-AU 的「最大刻绘宽度」在不同厂商资料里有 600 / 615 / 630 三种说法。
本项目**默认取最小值 600mm**：幅面设小只是排版受限，设大了是**刀走出材料、撞机甚至断刀**。

若机身铭牌确认为 630mm，在界面「机器型号」里改选 SC631E 预设即可。

### ⚠️ 坐标轴方向与对刀原点

**刻字机以操作者在材料上设定的对刀原点为基准：**
1. 操作者在机身面板用方向键将刀尖移动到材料角落。
2. 按机身面板的 **【原点】(Origin)** 键，此时该物理位置被固件设为局部 $(0, 0)$。
3. 刻绘任务从 $(0, 0)$ 开始正向刻入材料，任务开头**绝不下发 `!PG;` 机械归位**（避免冲毁对刀原点并撞导轨限位）。

标准轴向约定：
- **X 轴（第一参数）**：刀头（龙门左右导轨，幅面宽 600mm）
- **Y 轴（第二参数）**：走纸滚筒（材料进退，710mm 进纸方向）

> **这些都不在界面上调。** 它们是机器硬件属性，已在 SC631-AU 实机确认，
> 固化在 `machine/hpgl.js` 的机型预设里。界面暴露它们只会招来误改——
> 历史上正是反复调错这几项，才把「版面朝向」和「轴方向」搞混。
> 换机器或换控制板时才需要改预设，改法见下方「真机验证记录」。

## 真机验证记录

本项目的坐标轴逻辑是**在 SC631-AU 实机上反复调试验证的**。

### 已确认的机器事实

| 项 | 实测结果 |
|---|---|
| 物理电机分配 | 标准分配：刀头导轨为 `X` 轴，走纸滚筒为 `Y` 轴 |
| 步进分辨率 | 1000 步/英寸（0.0254mm/step） |
| 串口 | `/dev/ttyACM0`，115200 8N1，无流控 |
| 初始坐标基准 | 以面板【原点】为 $(0,0)$，开头不发 `!PG;` |
| **版面朝向** | **刻字时整版逆时针歪 90°**（方向正确、不镜像，纯躺倒） |

对应到标准配置：

```
swapAxes    = false    ← 不交换轴
axisX       =  1       ← 刀头正向
axisY       =  1       ← 走纸正向
layoutRotate = 90      ← 补偿版面朝向（顺时针 90°）
```

#### `layoutRotate` 是什么，为什么单独一个参数

**2026-10-05 实机结论**：把「SparkMinds」横排在画布上，刻出来整版
**逆时针歪了 90°**——方向本身是对的（没有镜像），只是整块版面转倒了。
所以补偿值是**顺时针 90°**。

物理原因：机器的走纸轴（710mm）与刀头轴（600mm）在固件里是反的，
而使用者是站在机器正前方按「左右 / 里外」描述版面的——
两个参考系差一次 90° 旋转，净效果就是整版转倒。

> 🔴 **它和 `swapAxes` 是两件完全不同的事，别再混着调**
>
> | 参数 | 管什么 | 填错的表现 |
> |---|---|---|
> | `swapAxes` | 图形是否**镜像** | 左右颠倒（一眼看出） |
> | `axisX/axisY` | 每根轴**往哪边是正** | 单轴镜像 |
> | `layoutRotate` | 整块版面**转多少度** | 整体躺倒 90°/180° |
>
> 历史上把前两者当成「版面朝向」来调，是本项目反复踩坑的根源。
> 三个维度正交，可以任意组合；旋转只接受 90° 的整数倍
> （入口会归一化，传 37° 会被收敛成 0°）。

> ⚠️ **改预设默认值时，必须同时检查板子上 `data/config.json` 里的历史值。**
> `config` 优先级高于预设，旧值会**静默覆盖**新预设——
> 表现是「改了代码没效果」，很容易误判成机器有问题。踩过一次。

### 实机确认的固件行为

这几条都是踩过才知道的，写在这里省得重复试：

| 行为 | 说明 |
|---|---|
| **必须先发 `IN;`** | 冷启动后固件处于未初始化状态，没有 `IN;` 会**静默忽略所有运动指令**。串口写入成功、任务显示「完成」，但机器纹丝不动——表现和「串口坏了」完全一样 |
| **不支持反向 SC** | `SC23622,0,...`（Xmin>Xmax）会让固件算出负缩放系数，整机失控（Y 轴飞转、X 轴狂奔）。SC 必须恒正序 |
| **`!PG;` 不回执完成** | 机械归位没有完成信号，串口又是流式的。上位机必须自己等（约 3 秒），否则新坐标会在归位途中生效 |
| **手动操作必须无条件抬刀** | 软件对刀状态的认知可能与机器真实状态不符（任务中断/串口重连后）。安全操作要无条件发 `PU;`，不能省 |

### 安全设计

几条「宁可多等、不可撞机」的处理：

- **任务开头先归位**：第一条 `PA` 是绝对定位，而机器开刀前停在哪是不确定的。
  从未知位置跳到图形起点会一路撞限位，所以强制先 `!PG;` 再定位（`homeFirst:false` 可关）
- **进给限速 + 急停**：所有手动动作都走任务队列，不绕过限速；急停只发 `PU;`，**不发任何移动指令**
- **SC 恒正序**：方向设错最坏是图形镜像，不会让固件进入负缩放
- **单次位移上限 200mm**，防止手滑
- **诊断用相对移动**：5mm、抬刀、来回一次，未归位也能安全测试
- **退出前抬刀**：服务重启/崩溃时不把压刀状态留给控制板

### 串口自动重连

服务启动时会**自动接回串口**，并每 3 秒重试一次。USB 重新插拔导致设备节点变化
（`ttyACM0` → `ttyACM1`）也能恢复。

> 之前没有这层逻辑时，每次服务重启机器都会「失联」，
> 界面上的手动按钮全部置灰，看起来像机器坏了——这是最容易误判的地方。

## 功能

### 导入与编辑

- **导入 DXF / SVG / HP-GL**，也能直接粘贴 HP-GL 指令
- **SVG 全图元解析与矩阵级联**：完整支持 `<path>`、`<circle>`、`<rect>`、`<ellipse>`、`<line>`、`<polyline>`、`<polygon>`，支持嵌套 `<g>` 分组与 transform 矩阵级联计算，彻底解决多图元 SVG 导入时圆形、长条矩形丢失问题
- **编组与解组（Group / Ungroup）**：
  - 导入含多个元素的复杂矢量图时默认以组形式管理，保持图层结构清晰
  - 支持选中图层一键「解组」（Ungroup），将各矢量拆分为独立图层单独调整
  - 支持多选（Shift / Cmd 点击）多个图层一键「编组」（Group）
  - 编组状态下对图层进行位移、缩放、旋转时，内部所有子元素几何实时同步更新，解组后位置保持严丝合缝
- **画布直观编辑**：选中图形后拖动移动、拖四角缩放、拖顶部圆点旋转（Shift 锁比例 / 吸 15°）
- **动态工作原点与刀尖准星**：
  - **实时刀头位置追踪**：画布与面板实时显现刻刀头物理位置与十字瞄准准星（⌖），直观掌控刀尖停靠点
  - **自定义工作原点（设原点 / 重置原点）**：移动刻刀头到目标下刀位置后，点击「设原点」即以当前位置建立工作坐标系，画布即时高亮红点原点标记与工作基准轴；可随时点击「重置原点」恢复机械零点
  - **相对原点编译**：CAM 编译自动按工作原点映射偏移，保证实际雕刻下刀点与画布设计绝对吻合
- **数值精确调整**：X / Y / 宽 / 高 / 角度，支持宽高比锁定、六向对齐、翻转、复制
- **快速文字**：内置单线字体（Stroker），专为刻字设计——普通字体转轮廓后在
  3mm 亚克力上会糊成一团，单线字才能刻清楚
- **两级几何抽稀与微小杂点滤除（De-speckle）**：
  - **CAM 工艺抽稀（RDP 自适应算法 + 纯共线合并）**：以 0.02mm 物理微步容差（小于力宇 1000 步/英寸的 0.0254mm 单步脉冲，远小于 0.2~0.5mm 刀尖刃宽）对过度采样的折线与位图描摹进行自适应抽稀，指令压缩率达 70%~95%（实测将 29.5 万行复杂刀路压缩至 9.4 万行），大幅降低 9600 串口物理传输与刻绘等待耗时。
  - **导入层微小描摹杂点过滤（1.0mm 阈值）**：自动检测并滤除位图描摹抗锯齿噪点产生的孤立微小闭合浮岛（$Max(W, H) < 1.0\text{mm}$ 且周长 $< 4.0\text{mm}$），杜绝刀尖在局部乱转划烂不干胶和挑字粘连。
  - **5 微米（0.005mm）无损预抽稀**：在图元进入画布前先行收敛冗余点与纯共线分段，保证超大复杂矢量图在前端画布缩放、拖拽与解组时极其丝滑。
- **指令层：HP-GL 连续坐标流合并（提速 20%~30%）**：
  在下发 HP-GL / DMPL 切割指令时，将连续折线点自动打包合并为批量坐标流（如 `PA x1,y1,x2,y2,...,x30,y30;`），消除数以万计重复的 `PA` 助记符与分号/换行符传输开销，字节流压缩率达 20%~30%，指令行数压缩 80%~95%，显著提升 9600 波特率下串口物理传输速度与下位机运动前瞻平滑度，同时完全兼顾下位机串口小缓冲区安全性。
- **Mac 键盘快捷键与焦点优化**：全面支持 Mac 的 `Delete`、`Backspace`、`Cmd+Backspace` 删除图层与 `Cmd+A` 全选；优化属性面板输入框失焦处理，按键在中文输入法状态下依然灵敏响应。
- **全屏加载等待遮罩**：导入与编译耗时操作期间展示半透明全屏遮罩与双语提示，锁定界面操作，消除卡死误解。
- 6 种材料预设（象牙卡纸 / PVC 发泡板 / 亚克力 / 不干胶 / KT 板烫金 / 薄纸），
  各自带速度和刀压

### 设备连接与手动控制

面板式控制，对应 Ucancam / 文泰的基本操作：

- **极简折叠式设备卡片**：连接面板对普通用户默认折叠透明，仅展示当前连接状态与机型名称；高级串口与波特率设置支持按需展开
- **真实连接心跳检测与断线自愈**：
  - 底层具备 1.5 秒周期性健康检测与读写错误断连机制，关机、断电或拔线立刻同步断连状态，彻底杜绝关机后 UI 仍虚假显示「已连接」的误导问题
  - 机器重新开机或 USB 重新插拔后，后台静默自动探测并恢复连接，普通用户无感自愈
- **方向键十字**（▲◀●▶▼），步长 0.1 / 1 / 5 / 10 / 25 / 50 mm
  - 按住连续移动，Shift 反向，桌面端也支持键盘方向键
- **抬刀 / 落刀 / 回原点 / 设原点 / 重置原点 / 进纸 / 出纸 / 抬刀回位**
- 单次位移上限 200mm，防止手滑

### 输出控制

- **物理运动学时序跟踪（Kinematic Virtual Pacing）**：由于商业刻字机固件多为开环单向接收架构（无串口双向状态回传），平台内置运动学仿真模型，根据切割速度、空移速度、抬落刀时延与归位驻留建模物理时序，解耦**机载缓存下发进度**与**材料物理刻绘进度**，提供真实的刻绘倒计时与执行状态。
- **任务队列与双阶段进度**：实时显示「缓存已载入行数」与「物理切割百分比 / 剩余时间」
- 暂停 / 继续 / 停止 / 急停
- 输出中可实时看到刀路预览与路径长度统计

## 资源占用

以下是在 **RK3399 / Armbian（4GB + 15GB eMMC）** 上实测的数字，不是估算。

### 磁盘

| 项 | 实测 |
|---|---|
| 部署目录总计 | **400 KB** |
| ├ `server/` | 232 KB |
| ├ `web/` | 152 KB |
| ├ `data/`（配置） | 8 KB |
| └ `package.json` | 4 KB |
| 依赖 | **0**（零 npm 依赖，不需要 `npm install`） |

400KB 是本项目「拷贝即用」设计的直接结果：不用 `serialport`（带 C++ 扩展），
串口走 `stty` + 文件描述符，HTTP 走 `node:http`，WebSocket 自行实现最小版。

`data/config.json` 会随保存配置缓慢增长，但只有配置项，量级在 KB。

### 内存

| 状态 | 实测 RSS |
|---|---|
| 空闲常驻 | **约 43 MB** |
| 单任务峰值 | 随图形复杂度上升，见下 |

43MB 主要是 Node 运行时本身（V8 堆 + 内部），**不是本项目的数据**。

任务期的增量取决于图形复杂度，实测（5000 段线，76KB 指令）：

```
指令全文 text      75 KB
lines 数组开销     约 450 KB   ← 每行一个字符串，JS 字符串对象有额外开销
```

**已经在做的一处优化**：任务历史保留 50 条，早期实现把每条的 `text` + `lines`
整份留着，几十 MB 常驻、跑几天只涨不降。现在入历史时剥掉重字段，
只留名字/状态/进度/字节数，界面照常显示。

### CPU

| 状态 | 实测 |
|---|---|
| 空闲 | **< 1%**（load average 约 0.05） |
| 输出中 | 约 1-3% |

**CPU 占用极低是串口波特率决定的**：9600 波特 = 960 字节/秒上限。
一份 76KB 的指令光传输就要 91 秒，机器走得比数据慢得多。
所以 CPU 瓶颈从来不在这里，而在机器的机械速度。

> 这也解释了为什么 `jobEngine` 要按字节数算延时、逐行喂：
> 不是为了省 CPU，是为了**别把控制板的数据缓冲冲垮**。

### 温度与稳定性

实测 CPU 温度 **45°C**（空闲），RK3399 是被动散热，这个温度很安全。
服务 `Restart=always`，崩溃会自动拉起；实测 `NRestarts=0`（稳定运行无重启）。

### 一句话总结

一台 RK3399 用 400KB 硬盘、43MB 内存、<1% CPU 就够了。
**瓶颈 100% 在刻字机机械本身**，不在这个服务。

## 精度

自检里有一项是「HPGL 编译后再解析回几何」的往返一致性验证：

| 指标 | 实测 | 说明 |
|---|---|---|
| 长度误差 | 0.0115% | 800mm 幅面上约 0.08mm |
| 包围盒误差 | 0.0003% | |

对比力宇标称重复精度 0.127mm，**指令生成的误差比机器本身的精度低一个数量级**——
说明瓶颈在机械，不在软件。

## 国际化

界面支持中英双语，点头栏的 `中 / EN` 按钮切换；首次访问按浏览器语言自动选择，
选择结果记在 `localStorage`。

三类文案分别处理：

| 来源 | 机制 |
|---|---|
| 静态 HTML | `data-i18n="key"`，属性用 `data-i18n-attr="placeholder:key,title:key"` |
| 动态 JS | `t('key', { vars })` |
| 服务端消息 | 两种语言一起下发，客户端挑（警告 `{zh, en}`、元信息 `{note, noteEn}`） |

三个刻意的设计取舍：

1. **不引第三方 i18n 库。** 前端是原生 ES module、零构建，
   需要 `npm install` 的库会破坏「拷贝文件即部署」这个前提。
2. **key 找不到时显示 key 本身**，而不是空白。
   空白看起来像「界面坏了」，而 `some.missing.key` 一眼看得见——静默失败才最危险。
3. **既有 API 字段保持中文语义。** `error` 仍是中文，英文挂在 `errorEn`；
   `pushLog(line, en)` 的 `line` 仍是中文。
   改动既有字段的含义，会让浏览器缓存里的旧前端显示空白。

```bash
node tools/i18n-check.js
```

体检内容：每条文案中英是否都有、两侧占位符是否一致、HTML 与 JS 引用的 key 是否都存在、
用户可见代码里是否残留未翻译的中文。它防的是最阴险的那类问题——
**key 根本没翻译**：界面悄悄夹着中文，而语法、启动、点按钮所有检查都是绿的。

自检里也断言了每条机型预设、材料预设、CAM 警告、手动控制 note 都带双语。

## 开发

```bash
npm run selftest     # 237 项自检，不需要接机器
node tools/i18n-check.js   # i18n 体检
npm start            # 默认 8080 端口
npm start -- --port 9000
```

**改动 `server/geom/path.js` 后要同步到 web**：

```bash
./deploy/sync-geom.sh
```

自检覆盖：几何不变量、HPGL 往返一致性、任务引擎状态机、
坐标轴镜像生成、版面旋转、机型幅面、串口写入路径、服务端双语完整性。
